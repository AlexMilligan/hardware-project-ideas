This is Alex's hardware notebook. The projects are for beginners, written by someone who is new to hardware too. Each page says what the thing is, what to buy only when a real list exists, and how you would know a step worked.

The pages are the canonical write-up. There is not a second README hiding inside each project.

## How sure is a page?

Two labels, on every project:

| Status | Meaning |
| --- | --- |
| idea | Not designed yet |
| draft design | A plan exists. Parts are not ordered and nothing is built |
| parts ordered | Parts are on the way or in hand. Not built |
| desk test | Something runs on the bench. Not worn or finished |
| built | Made as the page describes |
| abandoned | Stopped. The page says why |

| Evidence | Meaning |
| --- | --- |
| unbuilt | No hardware has been assembled for this project |
| hardware untested | The wiring or parts have not been checked on the bench |
| firmware untested | Code for this project has not been run on the hardware |
| verified on bench | The check named on the page was done, and it passed |

A project can carry more than one evidence tag. **Verified on bench** replaces the untested tags only for the check that passed. Nothing here has that tag yet.

:::note
A careful plan is still a plan. If the evidence line says untested, do not treat the parts, the wiring, or the code as proven.
:::

## How warnings look

Safety notes and other "read this first" lines use Starlight asides:

:::note
A note is context that is easy to miss, such as a sample rate or a missing measurement.
:::

:::tip
A tip is a small way to stay oriented, such as testing the last change before you change something else.
:::

:::caution
A caution is a real chance of a bad result: distortion, a wrong pinout, an untested upload.
:::

:::danger
Danger is reserved for harm, such as a lithium battery that can burn if it is shorted or crushed.
:::
